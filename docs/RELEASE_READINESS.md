# Проверка готовности Xover к релизу

Дата проверки: 27 сентября 2026. Область: все шесть модулей, сборка, тесты,
протокол, настройки, интерфейс, работа аудиоадаптера и упаковка.

## Статус

Подготовлен кандидат для тестирования в доверенной VPN-сети. Это не подтверждение
готовности публичного сетевого сервиса или всех поддерживаемых музыкальных сайтов.
Ниже отдельно перечислены выполненные проверки и оставшиеся условия выпуска.

## Исправлено

- VPN-адреса хоста и подключения, порт, opacity и закрепление окна сохраняются
  в `~/.xover/settings.properties`. Запись выполняется в фоне через временный файл;
  штатное закрытие сохраняет последнее изменение. Сворачивание сохраняет вкладку и поля.
- У анимаций кнопок, вкладок и размера окна согласована плавность; убрана непрерывная
  тряска. Перетаскивание следует за указателем, а ползунок позиции не перебивается
  обновлениями воспроизведения. Запуск/остановка сервера вынесены из потока интерфейса.
- Play ожидает готовности хоста и каждого слушателя. Подтверждения имеют идентификатор
  загрузки; клиент сначала синхронизирует часы. Повторное выделение трека создаёт новую
  загрузку. Ошибки, Pause, смена трека, отключение и тайм-аут отменяют ожидающий запуск.
- Новый слушатель приостанавливает играющую группу до своей готовности. При отключении
  участника автоматическое продолжение отменяется; хост может явно нажать Play снова.
- WebSocket-команды уходят последовательно; ответы синхронизации часов адресованы
  конкретному клиенту. Старые подключения и завершения прежних загрузок отбрасываются.
- Чтение позиции JavaFX больше не блокирует поток интерфейса. Отменённые операции
  разрешения URL прерываются; дочерние процессы завершаются при отмене.
- Токен Яндекс Музыки отправляется только на HTTPS API исходного сервиса; запросы
  метаданных на сторонних адресах не получают токен, автоматические редиректы отключены.
- Хост слушает указанный VPN-адрес. Системный шрифт заменяет встроенный файл, для которого
  в репозитории не записана лицензия; этот файл исключён из ресурсов дистрибутива.
- Архивы включают README, LICENSE, пример конфигурации и документацию. Релизный workflow
  собирает обфусцированный ZIP, сохраняет mapping и создаёт SHA-256; ручной запуск workflow
  без тега не публикует релиз. Публикация в рамках этой проверки не выполнялась.

## Автоматические проверки

```powershell
.\gradlew.bat clean build :app:releaseObfuscated --no-daemon
```

- Тесты приложения: валидация URL, диагностика ошибок, оценка часов и 23 сценария
  барьера готовности с управляемым временем, без ожиданий реальной сети.
- Четыре теста настроек: восстановление адресов/opacity, значения по умолчанию,
  повреждённые значения и замена файла без оставшихся временных файлов.
- Два интеграционных теста Ktor: порядок 40 команд и идентичность отправителя;
  реальный локальный хост с двумя клиентами, один из которых загружается медленнее.
  Аудиоплееры в этих тестах подставные: это проверка протокола, а не декодирования MP3.
- Обычная сборка и создание обфусцированного архива проверяются отдельно от реального
  воспроизведения. Результаты JUnit находятся в `<module>/build/reports/tests/test/`.

## Оставшиеся риски и приоритеты

| Приоритет | Наблюдение | Следующее действие |
| --- | --- | --- |
| До широкого выпуска | `/sync` не имеет кода приглашения/аутентификации; используется `ws://`. | Ограничить использование доверенной VPN; добавить подтверждение участников и аутентификацию до работы в недоверенных сетях. |
| До обещания непрерывной синхронизации | JavaFX READY означает готовность к запуску, а не скачивание всего файла. Буфер может закончиться позже; часы и устройства могут расходиться. | Добавить состояние buffering, общую паузу/возобновление, сравнение длительности/идентичности аудио и коррекцию дрейфа; при требовании полной загрузки — ограниченный дисковый кэш. |
| До массовой раздачи | Архив содержит платформенные JavaFX/Compose-библиотеки сборочной ОС, без собственного JRE. | Явно маркировать ОС; подготовить `jpackage` с JRE, подписью и тестом установки на чистой Windows. Для macOS/Linux нужны отдельные сборки и проверки. |
| Высокий | SoundCloud зависит от разбора страниц и внешних инструментов; Яндекс — от токена и поведения внешнего API. | Добавить контролируемые интеграционные проверки, общий бюджет времени запроса и ясные ошибки доступа; не заявлять поддержку источника без проверки реальными аккаунтами. |
| Высокий | Валидатор URL проверяет литералы адресов, но не все DNS-ответы/цепочки редиректов. Некоторые ответы HTTP и вывод процессов читаются целиком. | Централизовать сетевую политику: лимиты размеров, проверка каждого назначения и редиректа, общий тайм-аут. |
| Средний | Лимит кадра — 64 KiB; большой плейлист может его превысить. Лимиты числа участников и частоты сообщений не заданы. | Добавить лимиты в UI/приложении, пагинацию или дельты плейлиста, ограничение частоты сообщений. |
| Средний | Один повреждённый клиентский пакет может перевести хост в состояние ошибки. | Изолировать ошибки отдельных подключений и закрывать только нарушившего протокол участника. |
| Средний | `ListeningSessionService` объединяет плейлист, сетевую сессию и планирование; логика защищена монитором. | Выделить барьер готовности и управление плейлистом в небольшие объекты, сохранив сценарные тесты. |
| Средний | Нет проверки зависимостей на уязвимости, SBOM, проверок всех лицензий зависимостей и подписанных артефактов. | Добавить эти проверки в процесс выпуска; текущая сборка не доказывает отсутствие уязвимостей. |
| Позже | Плейлист, выбор роли и позиция окна не сохраняются; нет автоматического переподключения. | Добавить по отдельности, с миграцией формата настроек и явными правилами восстановления сессии. |

## Ручная приёмка перед публикацией

- На двух реальных компьютерах в целевой VPN проверить MP3, SoundCloud и Яндекс Музыку
  с доступными учётными данными. Медленный клиент должен удерживать обоих до готовности.
- Проверить ошибку загрузки, отключение VPN, смену трека во время загрузки, повторное
  подключение, Pause во время ожидания и перемотку во время воспроизведения.
- Проверить совместный звук в течение 20–30 минут и после сна/пробуждения компьютера.
- Проверить масштаб экрана 100/125/150%, повторное открытие окна, opacity и восстановление
  настроек после обновления приложения. Оценку плавности провести на целевом устройстве.
- Распаковать ZIP в путь с пробелами на чистой Windows с JDK 21; проверить запуск,
  воспроизведение и закрытие. Проверить также обфусцированный вариант с реальными источниками.
- Обновить номер версии и тег согласованно. Обе стороны должны использовать протокол 2;
  новая сборка не совместима с прежним протоколом. Сохранить mapping именно этого архива.

Поведение READY и ограничения streaming описаны в
[документации JavaFX MediaPlayer](https://openjfx.io/javadoc/21/javafx.media/javafx/scene/media/MediaPlayer.html).
Подходы к анимациям и обновлению графического слоя сверены с
[руководством Compose](https://developer.android.com/develop/ui/compose/animation/quick-guide).
